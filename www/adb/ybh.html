ybh.adb 製作說明（瑜伽師地論漢文集成）

ybh.adb 把十七部漢譯瑜伽系論書合成一顆資料庫：《瑜伽師地論》本論一百卷為中心， 周邊的釋、記、科判、隨論一起放進來，並把每一處科判與注文用座標指回《大正藏》冊 30 的原文那一行。 它的原料不是 XML，而是法鼓文理學院（DILA）的校勘注記 Markdown——一份放進 raw/ 就可以用 Obsidian／Docsify 雙鏈瀏覽的檔案庫。本文記錄從那些 md 到一顆 .adb 中間的幾步關鍵加工， 以及這一版做不到的地方。

數據提供者：耀悟法師、法鼓文理學院（DILA）。 本檔以 CC0（Creative Commons Zero）釋出，可自由使用、改作、再散布，不需授權登記。 本庫不含大正藏文字：跨庫連結只存「頁欄＋行窗」座標，實際經文由讀者自行下載 taisho.adb （依 CBETA 授權）；兩者放在同一資料夾時連結才會生效。

二、從 GitHub 的 md 到 adb：幾步關鍵加工

1. 文獻身分先鑑定，不信現成清單

原料的 README 有一份 38 條的系列對照表，實測其中 23 條是錯的——例如 T1604 被標成別部、 AS-sP／AS-sG／ASBhT 被標成「藏文」其實是梵本， 真正藏譯丹珠爾的是 CT… 那個前綴。所以系列歸屬一律改以 DILA 自己的權威略符表為準 （已存檔比對），README 不作為任何 metadata 來源。這一步決定後面所有的書名、語言與連結是否對。

2. 選檔與語言覆核

只收漢文十七部；每檔另算 CJK／梵文（Tibetan、Roman）字元佔比做語言覆核， 漢文檔的 CJK 比例應壓倒性——偏低的會被點出來人工看，避免把梵藏本誤混進漢文庫。

3. 把 Markdown 的隱含結構變成標籤

DILA 檔裡的结构是「標題行 + ^kpD… 區塊錨 + Obsidian 雙鏈 + [^n] 腳註」。轉檔時： 著作成篇、卷成章、科判依每部一個字族標記（本論 科NN、論釋 科釋NN、 披尋記 科漢NN…共十六個家族），腳註成 註／釋，校勘附編行尾的 ^appID 在行首補一個 <錨 n/> 讓校注引用有落點。

有一個計數規則踩過坑：只認「標題行定義」的 kpD，文內引用行不算定義。 早期用寬鬆比對時，「跨卷撞號」被誇大成十萬條，實際只有千分之幾。

4. 目錄樹要餵給「產品真正走的那條碼路」

閱讀器有兩條建樹路：命令列的 loadTree 與介面實際用的 buildTree， 後者的規則是「父節點用自己實例上的 t= 宣告子鏈；沒被任何父宣告的標籤一律當根」。 所以光靠 <篇 t="章"> 不夠，必須 <章 id="T1579-1" t="科01,…,科54."> 自宣告—— 否則十六萬科判在介面裡會全成根節點平鋪。另外總目錄另設一組零寬小詞彙（書目／卷次） 藏在篇、章行內，避免 篇.t 那條五十六層大鏈跨樹污染——總目錄因此從 24,213 行／75 ms 縮回 377 行／3 ms。

5. 互鏈分四層，各管一件事

標記做什麼讀者的感受
<聯 i="taisho?30p279a#34-40">跳到另一庫的精確位置點「CBETA」翻到大正那一欄，該句被塗紅
<嵌 i="taisho?…" j="34-40" n="原文"/>不離卷的行內速覽原句就在注文旁邊展開，不用跳走
<節聯 n="T1579-51#kpD51-003">庫內科判節點定位點目錄與點正文游標同步
<融 i="ybh?…" max="24"></融>把同一份論本就地填進任何科判勾「以科文融合顯示」即見論文；論本只有一份，文字不被複製

max 的單位是 adb 的「行」而非字元（實測 max=200 會拉出一萬七千字的大殼）， 24 是經過分佈取樣的防呆值，搭配閱讀器的「繼續展開」使用。

6. 行窗從哪來：引擎檢索，再用產品自己把關

窗（j="起-迄"）不是猜的，流程是：

  • 取該科判的正文起句，用連寫階梯（先 10 個漢字，不中就 7、5）送進閱讀器的檢索引擎定位—— 全程不把大正藏全文抽出來，避免把另一份版权文本帶進建置管線。
  • 命中後 greedy 延伸成最長一致片段，再換算成該頁的漢字偏移。
  • 最後一道閘門是產品自己的渲染器：逐條呼叫 renderEmbed， 要求回傳的 <mark class="xrefHit"> 漢字數恰好等於 迄−起，且窗首六字與引文相符； 不符合者就地剝窗（降級為純頁欄連結）。所以本庫寧可少給窗，也不發一個「點開是別句話」的錯位窗。

這一版（v26）就是沿這條閘門把 483 條候選裡過閘的 468 條重新算成逐字窗， 行內速覽由 40,786 增至 41,254 條。剩下的候選分成「唯一性太短」「靠較寬鬆的片段邻近法救回」 「同一句在大正出現多處需人工消歧」三類，逐條清單另附在原料倉庫的複核檔裡。

7. 兩套科判制式不同，不能硬對

《披尋記》用天干地支層級（甲、乙…子、丑…），其序號是父內編號（換父即復位）； DILA 的 kpD 是卷內流水。兩套數值直接互查只有約兩成對得上，必須按縮排重算父內序、 再比標題前綴與行距。另有一類大綱檔（-k）其實是拍平清單——父層資訊在源檔已失。 處理規則是：節點數與主卷逐部一比一鏡像、正規化標題吻合達九十五％以上者才還原父層； 不合格者（如本論、瑜伽論記）如實標為「平列」，絕不硬掛成一棵樹去虛構層次。

8. 驗收：六節全綠才算這一版做完

  • 庫內錨點：94,632 種目標逐條解析，FAIL 0。
  • 跨庫頁欄：29,612 種 taisho?… 座標全部能在 taisho.adb 解析出 VA，FAIL 0 （頁欄鍵一律含冊號並轉成數字比對——大正有 85.8％ 的「頁號＋欄」組合跨冊重複，丟冊號會靜默查到別冊）。
  • 段落窗：10,200 條注文段落 ref 從已部署的 adb 位元組回讀，而不是從中間檔。
  • 目錄樹回歸：走介面那條碼路，35 頁籤／17 根／377 節。
  • 融合殼：21,975 枚成對、無自閉合，抽樣取段全部可填。

三、目前做不到與已知缺口

  • 死錨 273 種、涉及引用 1,475 條（本檔隨附複核清單，本版重算數字不變）。其中約 96％ 集中在 T1584《決定藏論》與 T2801《瑜伽論分門記》——這兩部的科判 DILA 自己也標注尚未編完， 屬於源頭缺口而非轉檔錯誤；等 DILA 補編後重建即自動癒合，本庫不把它們硬改成「最近的一個科」。
  • 反鏈（「這一頁被誰引用」）對本庫目前恒為空：閱讀器建反鏈索引時要求來源庫有「頁」層， 而集成式文獻沒有這一層（本庫只有集／篇／章／卷次／科）。已連同重現數據回報閱讀器端，待其放開該條件。
  • 梵本與藏譯不入庫，故無法在本檔內做漢梵、漢藏對照。
  • 科判「逐字窗」目前覆蓋本論科判的約四成；其餘屬義引（注文並非逐字抄錄論文），本質上無法用逐字窗定位。
