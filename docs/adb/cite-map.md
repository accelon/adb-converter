# 引用對應表（cite map）：讓「講義 ↔ 原書」的連結不必每次重掃原書

作者 2026-11-01。這是給 **builder**（任何把 docx 講義轉成 adb 的流程）複用的通用設計，
第一份實作在 `fuyan`（釋厚觀《空之探究講義》→ ys.adb）。

## 1. 問題

講義引用原書的寫法是「《書名》，第X章，第Y節〈標題〉，p.NN」，有時再加「，注N」。
若每次重建都拿這些引文去掃原書（ys.adb 25 MB、7 萬頁），一次要幾十秒到幾分鐘；
而講義 docx 每次只改幾個字、幾個注號，重掃整本原書並不划算。

## 2. 關鍵觀察（穩定性假設）

| 東西 | 會不會變 | 說明 |
|---|---|---|
| 引文文字（書名＋章節＋標題） | **幾乎不變** | 講義是從原書複製貼上，作者只會在句子前後增減 |
| 頁碼 `p.NN` | 會變（換版、改頁） | 只能當「提示」，不能當 key |
| 注號 `，注N` | 會變（重編） | 同上 |
| 原書的頁 id／字元位置 | 會變（原書重建） | 用「文字」重新定位，不用座標 |

→ **以「正規化引文」為 key，值是「原書頁 id＋字元範圍 j」**。

## 3. 資料結構

`data/<book>-cites-map.tsv`（Tab 分隔，一行人為一筆）：

```
# key	yis頁	j	種類
《空之探究》，第一章，第三節〈空與心解脫〉	38p0020a		章節
《空之探究》，第一章，第七節〈空與空性〉，p.54	38p0054a	66-86	引文
《中觀今論》，第一章，第一節〈中道之內容〉	9p0005a		章節
```

- **key**：`《書名》，第X章，第Y節〈標題〉`（可選 `，p.NN`）。比對前先做正規化：
  去標籤、去空白、全形/半形統一。
- **ys頁**：目標資料庫的頁 id。
- **j**：目標頁內的漢字範圍（`a-b`），有引文比對時才有；沒有就只跳到頁／節開頭。
- **種類**：`引文`（用引文定位，最準）／`頁碼`（用引用頁碼）／`章節`（用節標題）。

檔案可 commit、可 diff；作者可以直接手改（加一筆或改一頁）。

## 4. 流程

```
extract（慢，偶爾做）            apply（快，每次重建都做）            verify
docx → 標記 → 找引用 ─┐        新標記 → 查表 → 包 <聯>  ─┐        壞連結 = 0？
  掃原書 → 建表 ─────┴─→ map ──→ 表裡沒有的少數才掃原書 ──┴─→ 打包
```

- **extract**：只在「第一次」或「原書重建」時做；輸出整份 map。
- **apply**：每次 docx 重建後做，只查表（O(1) hash），不碰原書。
- **fallback**：表裡沒有的 key（新加的引文）才去掃原書，掃到就回寫 map（map 越用越完整）。
- **verify**：所有 `<聯>` 的目標頁必須存在；不存在就拆掉標籤（不能讓點擊落空）。

## 5. 為什麼這樣能省時間

| 步驟 | 每次重建的成本 |
|---|---|
| 掃 ys 全文（舊） | 25 MB × N 筆引用，數十秒～數分鐘 |
| 查表（新） | 157 筆 × O(1)，毫秒級 |
| 只有新引用要掃 | 通常 0–5 筆 |

## 6. 擴充

- 同一個 map 可以放多本書（key 以書名開頭），或每本書一份。
- 若原書也重建，map 的「ys頁」會失效：用 `j` 對應的文字重新定位一次即可
  （map 本來就存了「文字→位置」的關係，重掃只需對有 j 的那幾筆）。
- 注號（`，注N`）不進 key；要連到注文時，用「注N：」後面的文字當第二層 key
  （見 `notej` 系列實驗；尚未定案）。
