# 句對齊資料的 adb 容器（草案，等 sz 確認）

> 2026-11-03。sz 正在做「先詞對齊、再回頭校正句對齊」（`D:\2026\sz\docs\sentence-alignment.md`），
> 產物是 `out/sent4-<db>-<book>.tsv`。閱讀器要能「點 cs 的第 3 句 → 看譯本的第 2 句（分數 0.82）」，
> 就得有一份進了 adb 的對齊表。這頁只定**契約**，不定 UI。

## 1. 為什麼要進 adb

- 閱讀器只讀 adb（桌面／網頁一致），不讀 `out/*.tsv`。
- 對齊表是「段 → 句對」的清單，很小（四部 6,554 段、每段幾句），適合一個未壓縮容器。
- 動到 UI 之前先把契约定好，sz 那邊才不會白做工。

## 2. 建議的容器（每個譯本 adb 各帶一份）

```text
align     1 block，未壓縮 UTF-8 JSON Lines
["ALIGN1", 6554]
["cs","dn1.7",3,3,0.82]
["cs","dn1.8",4,5,0.61]
```

欄位：`[來源庫, 段, 來源句, 譯本句, 分數]`

- 一個「來源句 → 譯本句」一列；`1:N`／`N:1` 就是同一個來源句出現多列、或同一個譯本句出現多列。
- 只放**有對齊**的句；沒有詞錨、被歸併的句子分數記 0（UI 顯示「待人工核」）。
- 段用 `塊.段` 的字串（`dn1.7`），不要用行號——行號會隨重切改變。
- 譯本庫自己的句號，就是它 adb 裡的「有文字的行」序號（與 `addressing.md` 的 `:句` 一致）。

## 3. 閱讀器端（實作時）

- `align` 存在 → 段對照抽屜／lex-pane 的「對讀」按鈕才出現（capability，不是寫死）。
- 分數低於門檻（暫定 0.2）標「待核」；空位（只有一邊有句）標「可能漏譯／衍文」。
- 沒有 `align` 的庫，行為完全不變（同今天的 `parallel` 群：沒有宣告就不出現）。

## 4. 待 sz 決定

1. 容器名用 `align` 還是 `parallel`（怕與 `<集 p>` 的平行群混淆）。
2. 分數要不要分「高信心」旗標，或只給分數讓 UI 自己判。
3. 十個譯本都各帶一份，還是集中放在 `cs`（來源庫）帶全部目標？前者查詢快、後者檔案少。
