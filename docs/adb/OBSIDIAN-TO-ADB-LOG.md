## 2. 需求逐輪：原話、判讀、落點

### 2.1 第一輪

> 「《論語句讀新詮》.zip 是 obsidian vault。請評估轉進 accelon26 的方案，最好不要人類介面，一鍵成 adb。」

**判讀**：不要 GUI、要一鍵；「轉進 accelon26」＝ 產出的東西要能被 accelon26 讀。
**落點**：評估文件 ＋ `tools/md2adb.ts`（CLI 原型）。
**事後看**：先做 CLI 是對的 —— 可重跑、可切片、可對拍，bug 定位比在 UI 裡快得多。但「不要人類介面」我讀成「不做 UI」，於是交了一支命令列；第二輪才知道作者的意思是「不要另一支轉檔程式，直接長在 accelon26 裡」。差別在**誰來按那個鍵**，不在於有沒有按鍵。

### 2.2 第二輪

> 「小圖也打包進去吧，你能識別 obsidian `![[ ]]` 嵌圖功能吧。加入 adb 旁邊加上「加入 obsidian」功能。http 版產生到 下載。桌面版放在 執行檔文件夾。記得更新 adb 清單。」

一句話六件事，逐項判讀：

| 原話 | 判讀 | 落點 |
|---|---|---|
| 小圖也打包進去 | 預設打包 vault 裡**每一張**圖，不是只打包被引用的 | `planVault` 預設全收；CLI 另留 `--referenced-only` 反向開關 |
| 識別 `![[ ]]` | Obsidian 附件語法，含 `![[圖\|alt]]` | 內嵌掃描（§6.3 重寫過一次） |
| 加入 adb 旁邊加「加入 obsidian」 | 選單一列、兩個入口（資料夾／zip） | `dbs.ts` 兩列 |
| http 版產生到「下載」 | 瀏覽器不寫任意路徑，走瀏覽器下載 | `vault-import` 網頁分支 |
| 桌面版放執行檔文件夾 | 存 exe 旁，不是 cwd | Go `SaveAdb` ＋ `refreshHostDbs` |
| 更新 adb 清單 | 存完就重掃，清單要立刻出現新庫 | `ListAdbs` 掃 cwd ＋ exe 目錄 |

「小圖也打包」這一句是這輪最關鍵的資訊：它把預設值釘死了。漏圖的症狀是「某幾頁空白」，比 adb 變大難查得多。

### 2.3 第三輪

> 「adb 不能用 book.adb，讓用戶輸入文件名（含與不含 .adb 皆可）。」

**判讀**：命名權給使用者；要防呆（空字串、只有 `.adb`、Windows 不合法字元、非 ASCII 的 dbname）。
**落點**：`src/vault-name.ts`，刻意寫成不碰 DOM 的純函式。
**事後看**：把「命名」抽出來是這輪最省事的決定 —— 測試不必開瀏覽器，`lunyu`、`lunyu.adb`、`論語`、`a<b>c` 這些案例全部在 CLI 裡跑。

### 2.4 第四輪

**判讀**：我當成授權，直接首發。
**事後看**：這是問句，不是命令。當時該回的是「要發哪一版？資料庫要不要一起上？」—— 少問這一句，就有了 §5。

## 4. 卡點與修法

### 4.1 zip 解壓太慢（2 分鐘 → 78 ms）

第一版用 `DecompressionStream` 逐筆解 zip 條目，1,299 條目要 **約 2 分鐘**，看起來像當掉。
量測後自己寫 `src/inflate.ts`（RFC 1951），同一份 vault **78 ms**，並用 zlib 對拍逐位元組一致。
教訓：瀏覽器內建 API 不一定快，尤其是「每筆一個 stream」的用法。

### 4.2 搜尋摘要切進標籤裡

摘要出現 `聯 n="令">令色` 這種殘骸 —— 命中位置落在標籤文字裡。
修法：`indexOfOutsideTags`（找命中時跳過標籤區間）＋ `snapOutsideTags`（把邊界推到標籤外）。

### 4.3 路徑列顯示 `#136`

目錄深處的節點沒有名字，breadcrumb 只好顯示 VA。
修法：`fillCachedLabels` 讀 `caches/<tag>`（建庫時把每個實例的內文存成名稱表），不再回推文字。

### 4.4 選資料夾會觸發兩次

`change` 事件對同一個選擇來兩次，第二次看到 `busy` 就顯示「正在轉換上一個…」，像錯誤訊息。
修法：`busy` 時靜音（`console.warn` 就好），不要把內部狀態當錯誤丟給使用者。

### 4.5 桌面版變 console 程式

本機 `go build` 沒帶 `-H windowsgui`，雙擊會先開一個黑窗。
修法：重 build 並用 `tools/pe-subsystem.ts` 驗 `subsystem=2`；順手把這個檢查寫進 `release.ts`，之後不會再忘。

## 6. 另一個對話的修正：筆記裡的 `<`、`>`、`&`

### 6.1 現象

作者在另一段對話回報：vault 裡只要有筆記帶 `<`、`>` 或 `&`，按「加入 Obsidian」就整個失敗，狀態列出現：

```
加入 Obsidian 失敗：line contains <, > or & (would corrupt the markup): …
```

不是那一行失敗，是**整個庫**失敗：`planVault()` 直接 `throw`，`vault-import` 接住後只 `setStatus`，沒有任何部分成果。結果是那本書一個字都產不出來。

### 6.2 根因（三層，缺一層都不會好）

| 層 | 問題 | 證據 |
|---|---|---|
| 授權端 | 把 `<>&` 當成「會破壞標記」而拒收 | 舊碼 `const HOSTILE = /[<>&]/` 就 `throw` |
| 格式 | adb 是行式 XML 方言，這三個字確實是結構字元 | `tokenize.ts` 的 `isStrongPair`／`getPair` |
| 讀取端 | 只改寫入的話，畫面會原樣顯示 `&lt;`；在錯的層解，解出來的 `<` 會被當成標籤 | 渲染器 `emit()` 收到的是「已切好的文字片段」 |

關鍵在第二、三層之間：**格式本身早就允許這些字**，只要用 XML 實體寫（`&lt;`、`&gt;`、`&amp;`）。`tools/xml-lint.ts` 的規則正好證明這點 —— 它把「裸 `&`」列為 `entity` 問題，`&amp;` 不是。

所以這不是格式限制，是**授權端自己加的限制**。整件事的修法方向因此不是「繞過格式」，而是「照格式本來的寫法寫，並在讀的一側還原」。

### 6.3 修法

**寫的一側**（`ts/src/vault-plan.ts`）

舊碼是「先 `replace` 圖片、再 `replace` 連結」，這種串接沒辦法安全跳脫：先跳脫會連自己產生的 `<圖>`／`<聯>` 一起跳脫，後跳脫會把 `<圖 n="a&amp;b.png">` 再跳一次。

改成**一次掃描**：一條 `INLINE_RE` 同時掃出三種內嵌語法（`![[附件]]`、`![](...)`／data URI、`[[條目]]`），掃到的「中間那段純文字」逐段 `encodeXmlText`，標記本身用 `encodeXmlAttr` 組出來。純文字與標記從此不會互相污染。

**新增** `ts/src/xml-entities.ts`

* `encodeXmlText`：`&`、`<`、`>`
* `encodeXmlAttr`：再加 `"`
* `decodeXmlEntities`：`&amp;`／`&#38;`／`&#x26;`，**只解一層**，未知實體原樣保留

**讀的一側**：七個點，少一個就露餡

| 位置 | 解什麼 | 不解會怎樣 |
|---|---|---|
| `render_accelon3.emit()` | 每一段正文 | 畫面顯示 `&lt;br&gt;`；摘要、搜尋片段也走這裡 |
| `render_accelon3.attrValue()` | `<聯 n="…">` 等屬性 | tooltip／標題露出實體 |
| `AdbReader.cachedStrings()` | 名稱表 | 目錄、詞典列名直接顯示 `A&amp;B` |
| `AdbReader.attrValue()` | attributes 的值 | 同上，另一個入口 |
| `vapa.nodeLabel()` | 節點名 | 路徑列（breadcrumb）顯示實體 |
| `scopes.wrappedText()` | 清單列名 | 標籤清單／詞條列顯示實體 |
| `doc-pane` 圖片名 | `<圖 n="…">` | 資源是用**檔名**查的，`a&amp;b.png` 查不到 `a&b.png`，圖就空白 |

整個修正 10 個檔案、+288 −67 行 —— 約四成（105 行）是測試。真正動到行為的只有「寫」的一側（`vault-plan.ts` ＋ 新的 `xml-entities.ts`）與「讀」的五個檔、七個點。

### 6.4 三條不變式（給下一個改這段的人）

1. **順序**：`decode → conv → esc`。先解實體、再套顯示轉換、最後 HTML 跳脫。順序反了，`&lt;` 會被跳脫成 `&amp;lt;`，畫面就出現實體。
2. **只解一層**：`&amp;lt;` 是文字 `&lt;`，不是 `<`。作者若真的想寫「&lt; 這四個字」，就是這樣寫進 vault 的。
3. **只解已切好的片段**：解碼只作用在 lineInfo 切出來的「不是標籤」的區間上，不在整行上做。在整行上解，`<` 會被當成標籤開頭。

另外 `wrappedText` 是「先剝標籤、再解」，順序不能反 —— 反了會把解出來的 `<` 當成標籤剝掉。

### 6.5 驗證

`ts/test/vault-plan.test.ts`（12 項，新檔）挑了六個關鍵斷言：

| 斷言 | 實例 |
|---|---|
| 含 `< > &` 的 vault 不再丟錯 | `甲 < 乙 & 丙 > 丁` → `甲 &lt; 乙 &amp; 丙 &gt; 丁` |
| blockquote 的 `>` 也跳脫 | `> 引用` → `&gt; 引用` |
| 連結目標與顯示文字都跳脫 | `[[般若\|空 & 有]]` → `<聯 n="般若">空 &amp; 有</聯>` |
| 圖檔名（屬性）也跳脫 | `a&b.png` → `<圖 n="a&amp;b.png"/>` |
| 集／篇／章／字頭都跳脫 | `<集 t="集">A&amp;B &lt;測試&gt;</集>` |
| 原本的 `&lt;` 只多一層 | `&lt;` → `&amp;lt;`，畫面仍是 `&lt;` |

再加上端到端那條：真的建一個 adb、讀回 `caches/字`，得到 `A&B`。

`ts/test/render.test.ts` 新增 3 項：實體解回原字且不成標籤、只解一層、連結的屬性與文字都解。

**沒有回歸的證明**：用修好後的程式重建論語，與修正前的 `build/lunyu.adb` **逐位元組相同**（3,871,803 B，sha `da48ae38…`）。原因是那份 vault 的正文本來就沒有這三個字 —— 修正只在需要時才生效，既有輸出一個 byte 都沒動。

**部品確認**：`wails/assets/index.html` 裡找得到解碼器（`amp: "&"` 那一段），表示 exe 真的帶了修正，不是只有原始碼改了。

當天全套單元測試：`bun run` 512 項 ＋ `bun test` 20 項 ＝ **532 項，0 失敗**。

### 6.6 交付：同一天、同一個版號重發

問題：當天 `02:08:34Z` 已發一版。若用當下時間，會出現兩個「2026-10-25」版本，使用者也分不清。

做法：

* `tools/release.ts` 加 `--build-time`（RFC3339 UTC，釘住建置時間），並在說明裡寫清楚「同一天重發同一版」的用法。
* 改版說明**就地改**當天那一筆的 `buildTime` 並加一條，不新增第二筆 —— changelog 上仍是「2026-10-25 一版，六條說明」。
* 建置與上傳照舊（GUI 子系統檢查、`versions.json`、`7z`）。

結果：`03:15:00Z`（本地 11:15），17,961,984 B，sha `689a9c6a…`。舊版使用者會看到更新提示 —— 版本比對以 `buildTime` 為準（`wails/update_test.go` 的 `TestCheckViaManifest`）。

### 6.7 沒做完的

| 項目 | 現況 | 影響 |
|---|---|---|
| 搜尋字面 `<`、`&` | 索引裡的 token 是實體形式（實測 `甲 &lt; 乙 &amp; 丙` → `甲`／`&lt;`／`乙`／`&amp;`／`丙`） | 查 `br` 找得到（`&lt;br&gt;` 會切出 `br`），查 `<`、`&` 本身找不到 |
| 編輯模式 | 編輯器直接改原始行，看到的是 `&lt;` | 編輯者要記得那是實體；存回不會再跳脫（沒有往返風險） |
| 導出文字 | 原樣帶實體 | 下游要自己解一層 |
| 語意取捨 | 既有庫若有人故意把 `&amp;` 當文字寫，現在會顯示成 `&` | 一層解碼的必然結果；實務上少見 |
| 文件 | 交接文件已補 §18.2；評估文件沒動 | 只讀評估文件的人不知道這件事 |

## 7. 覆盤

**做對的**

* 先 CLI 再 UI：管線先能對拍、能重跑，UI 只是外殼。
* 逐位元組對拍：Bun 與瀏覽器兩條路徑輸出相同；這次也用同一個方法證明「修正沒有動到既有資料」。
