# `<聯 j>` 字元級反鏈：實戰筆記（2026-10-28）

> 這份記的是把 `<聯 i q>` 升級成 `<聯 i q j>` 時，實際踩到的坑與可重複使用的流程。
> 規格本身在 `cbeta-adb-skill.md` §4；連結流程在 `backlink-skill.md`；舊庫升級在
> `old-adb-upgrade-skill.md`。這裡只記「為什麼會錯、怎麼驗」。

## 1. 座標系

```xml
<聯 i="taisho?8p848c" q="色即是空，空即是色；" j="52-60">色即是空，空即是色</聯>
```

| 欄位 | 意義 |
|---|---|
| `i` | `目標dbname?頁id`，accelon3 標準格式，不動 |
| `q` | 目標頁原文（純漢字），沒有 `j` 時用來做頁內文字比對 |
| `j` | 目標頁「可見漢字」索引 `起-訖`（0 起算、end 不含），只寫數字 |

`j` 的算法和 `xref.renderForeign()` 的 `lineHtml()` 完全一致：

- 從 `<頁 id="…">` 之後起算；
- 跳過 `<…>` 標記；
- 只數 `[\u3400-\u4dbf\u4e00-\u9fff\uf900-\ufaff]`（BMP 漢字）；
- 頁面取 2000 code unit（`maxChars`）。

**來源端**（`<聯>` 要包哪一段）用原始字元索引（連標點算）；**目標端** `j` 用漢字索引。
兩種座標不要混。

## 3. 七個實際踩過的坑

### 3.1 JS 的 `\b` 對漢字無效

`/<聯\b([^>]*)>/` 永遠不匹配，因為「聯」不是 ASCII word character，和後面的空白
之間沒有 `\b`。要用 `/<聯([^>]*)>/`。這個 bug 讓 `retrofit-j.ts` 第一次跑出
「links 0」。

### 3.2 `聯.i` 與 `聯.q` 的陣列索引不保證對齊

`ys.adb` 有 25,918 個 `聯.i`，但只有 25,671 個 `聯.q`（247 個內部連結沒有 q）。
直接拿 `q.values[k]` 配 `i.values[k]` 會錯位，驗證時會看到「q 和頁面完全無關」的
假錯誤。要嘛用 attribute 的 `pointers` 對到同一個 tag instance，要嘛直接解析
文字裡的 `<聯 …>` 標籤（最可靠）。

### 3.3 大正藏有重複的頁 id

例如 `31p613b` 有兩個 `<頁 id="31p613b">`：第一個只有 30 字，內容在第二個。
`ids.indexOf(id)` 只會拿到第一個，於是：

- `pageHan` 取到短頁，`q` 永遠對不上；
- 反向驗證會把正確的 `j` 判成錯。

正確做法：用頁的 **index**（`tags/頁` 的第 k 個）而不是 id 反查；要按 id 取頁時，
走訪 **所有** 同 id 的出現。閱讀器 `renderForeign()` 現在有 `q` 時會選「頁文含
這段 q」的那一次出現，再套 `j`。

### 3.4 `mapper.context()` 不是頁文

`mapper.context(pageVa, 0, N)` 從頁標記之後的 token 開始，會跨頁／跨重複頁，
拿它做「q 是否在這一頁」的嚴格驗證會過度寬鬆。第一版 `find-elsewhere.ts` 就是
這樣把 29 條判成「整句在頁上」，改用實際 block 的 `<頁>` 到下一 `<頁>` 之後，
只剩 **1 條** 真的在頁上。

**嚴格驗證**：從 `sourceText(block)` 找 `<頁 id="…">`，切到下一個 `<頁 `（或 2000
code unit），再比對 q。`verify-j.ts`、`find-elsewhere.ts`、`apply-elsewhere.ts`
都走這條。

### 3.5 正規化用於比對，不要用於儲存

異體字／繁簡要用 `canon()`（`expandToken`）對齊，否則「說／説」「歸／归」比對不到。
但 `canon()` 可能把傳統字映射成簡體；**存進 `q` 的必須是頁面原文切片**，不是
canon 後的字串。`j` 的索引兩邊都是漢字，長度不變，所以位置可以共用。

### 3.6 `q` 不一定是大正原文

`ys` 很多 `q` 是印順自己的改寫、拼接或頁內參照（例：「義後品中當廣」是 6 字
頁內交叉引用，不是經文）。這種再怎麼搜都找不到逐字對應，硬寫 `j` 只會標錯。
`j` 只能加在「q 真的能在目標頁找到」的聯上；找不到就留在 broken 清單。

### 3.7 前綴命中 ≠ 整句命中

全文檢索用 30→24→18→14→10→8→6 字前綴，6 字很容易命中別處。`ys` 577 條
no-match 裡，前綴命中 237 條，但整句真的在頁上的只有 1 條（`42p0020a` →
`71p177c`，已修）；修完後剩 576 條：237 條前綴、339 條完全找不到。要改 `i` 或補
`j` 前，一定要用**整句 q** 在實際頁文上再驗一次。

## 4. 中間反鏈要逐頁掛

`doc-pane.ts` 的 `paintReverseBar()` 原本只算文件**第一頁**的引用，把按鈕全插在
文件頂端。金剛經從 `8p748c` 開始，讀者跳到 `8p749a` 時會看到 748c 的
「初期 994a」按鈕，誤以為它掛在 749a。

現在改成：走訪文件裡每一個 `<頁>`，只拿那一頁的行文比對 `q`，按鈕貼在那一行；
找不到行的才退回該頁頁首。

## 5. 工具鏈

| 工具 | 用途 |
|---|---|
| `ts/tools/backlink.ts` | 新庫：抽引文、搜大正、套 `<聯 i q j>`、打包 |
| `ts/tools/retrofit-j.ts` | 既有 `<聯 i q>`：頁內精確＋寬鬆對位補 `j`，必要時把 `q` 換成頁面原文 |
| `ts/tools/repair-window.ts` | 頁內找不到時，試目標頁＋前後頁、單字命中率、寬鬆對位；必要時改 `i` |
| `ts/tools/verify-j.ts` | 把新 `j` 放回頁 id 的實際出現驗證；失敗就整條還原 |
| `ts/tools/find-elsewhere.ts` | 對 broken quote 跑全文檢索（SearchSession），找是否在別頁 |
| `ts/tools/apply-elsewhere.ts` | 套用全文檢索找到的 `i`／`j`（只套整句驗證通過的） |
| `ts/tools/broken-quotes.ts` | 產生 `broken-quote.md`／`ys-broken-quotes.tsv` |

## 6. 修復順序（建議）

```text
backlink.ts（新庫）
  → retrofit-j.ts（頁內精確＋寬鬆）
  → repair-window.ts（前後頁＋單字命中率）
  → verify-j.ts（實際頁文驗證，失敗還原）
  → find-elsewhere.ts（全文檢索找別頁）
  → apply-elsewhere.ts（只套整句驗證通過的）
  → broken-quotes.ts（剩下的列清單）
```

每一步都要保留「文字逐行不變、`頁.id` 不變、caches 不變、`聯.i` 數量不變」的檢查。

## 7. 閱讀器

- `render_accelon3.ts` 把 `j` 放進 `<a data-j>`。
- `xref.renderForeign(db, va, anchor, quote, range)`：
  - 有 `q` 時，先在同 id 的多個 `<頁>` 中選「頁文含 q」的那一次；
  - 有 `j` 時切 `pn[起,訖]`，必須等於 `q` 的漢字前綴才塗；
  - 對不上就退回 `q` 文字比對，所以錯的 `j` 不會標錯地方。
- 舊 accelon3 只會多存一個 `聯.j` 屬性，不影響閱讀；`聯` 是 skip tag，
  頁碼、VA、`頁.id` 都不變。
