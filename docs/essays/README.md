**畫公仔唔使畫出腸。**（作者 2026-11-03 定調）

## 文風（2026-11-03 由實際改稿歸納，作者確認）

1. **留白優先**：情緒點到就停，不替讀者命名感受。
   「明明是好事，卻有點想哭」已經說完了，不要補「這叫悲欣交集」。
2. **具體優先於抽象**：寫物件、動作、聲音、價錢，不寫概念。
   硬碟、掃描器、影印店的下午、粉塵落在褲管、土堆成小山。
3. **技術點到為止**：一個畫面就夠（「一句話，它做完」），不寫規格、不列清單、不下定義。
4. **一個比喻走到底**：牆、隧道、刀、燈、機器——同一組意象貫穿全篇，也跨篇回指。
   比喻是骨架，不是修飾；壓縮論證時不能把它刪掉。
5. **對比推進**：慢／快、貴／便宜、二十年／一句話、看得見／看不見。
6. **情感要誠實**：先承認怕（怕那二十年白挖）、承認慢、承認懷疑，再化解；不假裝豁達。
7. **短句、短段**：一句一段也可以，讓節奏呼吸。
8. **結尾回到意象**：海邊、雨季、燈——不總結大道理，不加「所以我們應該」。
9. **數字留模糊**：「幾年份的工」「幾個人的薪水」「好幾個冬天」；除非是事實陳述，不寫精確帳單。
10. **系列感**：同一批意象在不同篇之間互相回指即可，不必點題、不必解釋這是第幾篇。

## 改稿檢查表（動筆前八問）

1. 這一段是在**說理**還是在**讓人看見**？說理的，砍。
2. 有沒有替讀者說出他本來會自己想到的那句話？有，刪。
3. 比喻還在不在？被壓縮掉了，補回來。
4. 有沒有學術詞（論證、單位、結構、語義分層）？改成畫面或刪。
5. 情緒是靠形容詞（悲傷、震撼、感動）還是靠事實？改成事實。
6. 句子有沒有太長、太整齊、太像講稿？切短。
7. 結尾有沒有在教訓人？拿掉最後一句試試。
8. 通篇有沒有一個物件可以摸得到？（牆、土、燈、粉塵。）

## 格式

- 繁體中文；引號用「」；不用 Markdown 粗體在正文標重點，正文保持樸素。
- 一段一至三句；不加小標題、不列點（正文是散文）。
- 檔名就是文章標題（中文），一篇一檔。

## 失敗案例（真實發生過，別再犯）

| 我做的 | 作者的反應 |
|---|---|
| 在「明明是好事，卻有點想哭」後面補「古人叫它悲欣交集」 | 不必畫公仔畫出腸 |
| 為了收緊論證，把盾構機的比喻刪掉 | 「那個盾構機的譬喻就不見了？」 |
| 寫成大正藏冊頁碼 vs 語義分句的論證 | 「不必過於學術，重點在於抒情，感嘆盾構機的威力」 |
| 抒情時只寫「它很快、很方便」 | 要「過去付出巨大心血和金錢，如今寥寥數語便能搞定；正因昔日艱辛，才倍加珍惜」 |
| 只寫「它很強」 | 要寫出**難度與成本養出的直覺**——所以少走彎路 |

## 不要做

- 不要把系列文章塞成一篇，也不要替它寫導讀。
- 不要在文末加「總結」「啟示」「希望讀者……」。
- 不要把技術細節寫成可以拿去當規格書的樣子——那是文件，不是散文。
