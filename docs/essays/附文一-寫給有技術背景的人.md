# 附文一：寫給有技術背景的人

先說結論：那台機器不是魔法，是很多層東西疊起來；「一句話」能推動它，是因為那句話被翻譯成同一個問題。

## 一、地址綁內容，不綁版面

你可能先問：為什麼不直接用「冊、頁、欄、行」？

因為那是版面的座標。版面會重排：換一個版本、換一次印刷，同一句話就換行、換欄。拿它做跨版本、跨譯本的對齊，等於要求十幾份排版在同一個折頁上斷同樣的行。

所以我們把經文攤成一條連續的文字流，每個詞佔一個位置——是一個**計數**，不是字元位移。字元位移會因為缺字、異體、標點而漂；計數不會。行、段、句是另外的層，各自記住自己的邊界。版本？版本只是這條流上的一張對照表。

## 二、三層疊起來才有用

只有詞的位置，查得到、引不了：你知道這個詞出現在第八萬個位置，但不知道那是哪一句。

只有頁行，引得了、查不到：你指得出「某頁某欄某行」，但要問「這個詞在律藏裡出現幾次」，就得一行一行看。

三層疊起來，才有「引用一句話，同時追到一個詞」這種事。這不是設計美學，是使用上的必要。

## 三、一句話怎麼變成動作

你打「把這一段斷成句，十個譯本對齊」，中間發生的事其實很土：

解析成幾個詞組，每個詞去查 posting list，相鄰的取交集，再把位置回推成行、段、句，最後才在畫面上塗紅。快，是因為每次查詢都在查表，不是重讀經文。

## 四、幾個數字

- 目錄 74,219 列，只掛視窗附近五十到七十列。
- 日文索引 10,855 個詞、緬文 9,341、泰文 11,310——三個庫三套切法，不能共用假設。
- 一個詞的反查表：14.9 MB 的詞庫，建表 3.3 秒，查一次五毫秒以內。
- 搜「話題」四十筆，四毫秒。

快的是查與搬；慢的是定義單位。

## 五、還沒還的債

- **兩套切詞器**：桌面版有一段後端只會逐字切，跟索引不一致。現在用「某些查詢不走那個後端」擋住，但那是遮，不是解。正解是讓切詞只存在一處。
- **字元位移**：我們把「標題＋段」切成一塊塊之後，用字元位移標範圍的地方會少算前段的長度。目前沒有庫同時用到，所以還沒炸。
- **跨版本對齊**：高麗藏與大正藏的對照表是人工一格一格對出來的；錯一格，整段引錯。
- **虛擬清單的邊界**：只掛視窗附近的列，換來速度，代價是任何「數整棵樹」的斷言都要先全部展開。

## 六、如果你想接手

先讀圖紙：地址、層、切詞規則，還有哪一層是解釋。圖紙不對，機器只會更快地挖歪。

還有一件事：它不會自己喊停。停的判斷不寫在程式裡，寫在經驗裡——那是唯一不能外包的部分。

土會繼續動，但方向還是要有人看著。
